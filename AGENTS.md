## GitHub workflow

The owner authorizes the complete workflow below for finished project work in the public `stephenmccranie/civilization` repository: commit, push the task branch, create/update its PR, squash-merge it into `main`, and clean up that task's merged branch. Do this automatically after validation, without routine confirmation. An explicit user request to keep a branch/PR open or stop before merging overrides this default. Keep `main` as the verified working version.

1. **Start a focused task branch.** Inspect status, existing branches/worktrees and the current remote `main`. Start each coherent task, including documentation-only work, on a short-lived `codex/<task>` branch from current `origin/main`. Continue an existing branch for the same unfinished task; do not create a new branch for each follow-up. Keep unrelated features separate. Use an isolated worktree when needed to preserve concurrent or uncommitted work; do not reset, move or stage someone else's work.
2. **Commit useful checkpoints.** Keep commits focused on the task and stage explicit paths/hunks. Small development commits are fine; keep throwaway experiments local. Push useful task checkpoints for backup, and publish completed changes. Do not commit directly to `main` or use broad staging to sweep in unrelated files.
3. **Complete and verify the whole change.** Include code, runtime assets, affected authoritative documentation and appropriate checks from [testing](civilization-mod/testing.md). Inspect actual visual proofs when appearance changes, and run `python tools/check_docs.py` after documentation/path changes. Inspect the final staged diff and paths for unrelated work and private/local files. Diagnose and fix unexplained test failures, including flaky fixtures encountered during validation; do not merge by retrying until green, disabling assertions or silently accepting a failing suite. If a required check cannot be completed, report the limitation and leave the PR open.
4. **Publish one PR per coherent task.** Target `main`; describe the final behavior, actual validation and material limitations. Update an existing task PR instead of creating duplicates, and attach every created/updated PR to the Codex task. Incorporate intervening `main` changes without rewriting shared history; inspect the resulting diff and rerun checks when those changes affect the validated result. Verify the intended head and any configured required GitHub checks before merging; do not bypass repository protections.
5. **Squash-merge by default.** Once the task is complete and its relevant checks pass, squash-merge the PR so `main` receives one clear commit. Use a normal merge only when the user explicitly requests preserving the individual commits. Squashing through GitHub does not authorize force-pushing development branches or rewriting existing `main` history.
6. **Clean up only the finished task.** Confirm the PR is merged and covers the latest task head, fetch the updated remote, and fast-forward a clean local `main`. Delete that task's remote/local feature branch when no unfinished work depends on it. A squash merge will not make its original commits ancestors of `main`; confirm the PR's recorded head/merge result before deleting rather than relying on ancestry alone. Never delete a branch still used by another active task/worktree, discard uncommitted work, or remove ignored files during cleanup. Archive managed worktrees through the app's supported lifecycle when no longer needed; leave active worktrees and unrelated historical branches alone. Report merged PR, validation, any remaining limitations and cleanup exceptions.

**Publication boundary:** publish code, runtime resources, documentation and reusable tools only. Keep original art, editable art models and visual review history (`art/`, `concept_art/`), worlds, local configuration, credentials, caches and downloaded dependencies out of GitHub. Preserve the local full-project history branches (`local/full-project-before-github` and the legacy `master`); never push or delete them, and never use `git push --all`/`--mirror`. Never force-push or rewrite shared history without explicit authorization. Preserve the byte-stable `.gitattributes` policy because asset receipts hash their original sources.
